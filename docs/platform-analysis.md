# 持仓助手平台化方案分析

## 一、当前现状

### 现有功能
- 单用户本地应用，数据存储在 `localStorage`
- 支持A股实时行情查询、持仓管理、盈亏计算
- 导出/导入功能（通过URL参数迁移数据）
- 30秒自动刷新行情

### 数据模型
```javascript
{
  code: "600036",      // 股票代码
  name: "招商银行",    // 股票名称
  qty: 1000,           // 持股数
  cost: 35.5,          // 成本价
  createdAt: "2026-01-01T00:00:00",
  lastPrice: null,     // 最新价（缓存）
  lastChangePct: null  // 涨跌幅（缓存）
}
```

- **短线氛围**：侧重超短线、打板、低吸策略

- **优势**：实战氛围浓，短线高手聚集

1. **专注A股** — 国外平台不支持A股，国内雪球功能较重

4. **开源透明** — 代码开源，数据可迁移
5. **老师主页** — 每个老师独立页面，类似Patreon但专注股票

## 三、打赏功能方案分析

### 方案1：赞赏码（最简单）

**实现方式：**
- 老师上传自己的支付宝/微信赞赏码图片
- 观众打赏时显示二维码，手动转账
- 平台不参与资金流转

**优点：**
- 零成本，无需企业资质
- 1-2天可上线
- 无手续费

**缺点：**
- 无法追踪打赏记录
- 无法做打赏排行榜
- 用户体验一般

**适合：** MVP阶段、个人项目

---

### 方案2：第三方支付平台（推荐）

#### 2.1 爱发电（afdian.net）
```javascript
// 接入示例
GET https://afdian.com/api/open/query-user?user_id=xxx
GET https://afdian.com/api/open/query-order?user_id=xxx&page=1
```

**优点：**
- 个人可注册，无需企业资质
- 提供API可查询打赏记录
- 支持支付宝/微信
- 平台抽成5%

**缺点：**
- 需要用户跳转到爱发电页面
- 品牌露出

#### 2.2 赞赏通（zanshang.pro）
- 类似爱发电，个人可接入
- 提供嵌入式组件

#### 2.3 面包多（mianbaoduo.com）
- 知识付费平台
- 支持订阅制

---

### 方案4：虚拟积分系统

**实现方式：**
- 平台发行虚拟币（如"粮票"）
- 用户充值获得虚拟币
- 用虚拟币打赏老师
- 老师可提现（满100起提）

**优点：**
- 规避支付资质问题
- 可做平台运营活动
- 资金沉淀

**缺点：**
- 开发复杂度高
- 涉及资金池，有法律风险
- 需要ICP备案

---

### 方案5：打赏排行榜+打赏记录（无支付）

**实现方式：**
- 用户打赏后截图上传
- 管理员审核后展示
- 显示打赏排行榜

**优点：**
- 无需支付接口
- 营造打赏氛围

**缺点：**
- 无法验证真实性
- 运营成本高

## 四、推荐方案（分阶段）

### 阶段1：MVP（1-2周）
**采用方案1 + 方案5**
```
技术栈：纯前端（Vue/React）+ GitHub Pages
存储：localStorage + URL参数
打赏：赞赏码 + 打赏记录展示（手动审核）
用户系统：简单密码验证（无注册，邀请码机制）
```

**成本：** 0元
**适合：** 验证概念，种子用户

---

### 阶段2：正式版（1-2月）
**采用方案2（爱发电）**
```
技术栈：Next.js + Vercel
数据库：Vercel Postgres / Supabase
认证：NextAuth.js（GitHub/微信登录）
打赏：爱发电API集成
```

**成本：** 约100元/月
**适合：** 小规模运营

---

### 阶段3：商业化（3-6月）
**采用方案3（支付宝/微信）**
```
技术栈：Node.js + React
数据库：MySQL/PostgreSQL
部署：阿里云/腾讯云
支付：支付宝+微信官方API
增值：付费订阅、VIP功能
```

**成本：** 约500-2000元/月
**适合：** 规模化运营

## 五、技术架构建议

### 数据库设计
```sql
-- 用户表
CREATE TABLE users (
  id UUID PRIMARY KEY,
  username VARCHAR(50) UNIQUE,
  email VARCHAR(100),
  avatar VARCHAR(255),
  role ENUM('teacher', 'viewer', 'admin'),
  created_at TIMESTAMP
);

-- 持仓表
CREATE TABLE holdings (
  id UUID PRIMARY KEY,
  user_id UUID REFERENCES users(id),
  stock_code VARCHAR(10),
  stock_name VARCHAR(50),
  quantity INTEGER,
  cost_price DECIMAL(10,3),
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);

-- 打赏表
CREATE TABLE tips (
  id UUID PRIMARY KEY,
  from_user_id UUID REFERENCES users(id),
  to_user_id UUID REFERENCES users(id),
  amount DECIMAL(10,2),
  message TEXT,
  status ENUM('pending', 'completed', 'failed'),
  created_at TIMESTAMP
);

-- 关注表
CREATE TABLE follows (
  follower_id UUID REFERENCES users(id),
  teacher_id UUID REFERENCES users(id),
  created_at TIMESTAMP,
  PRIMARY KEY (follower_id, teacher_id)
);
```

### API设计
```
POST   /api/auth/register     # 注册
POST   /api/auth/login        # 登录
GET    /api/teachers          # 老师列表
GET    /api/teachers/:id      # 老师详情
GET    /api/teachers/:id/holdings  # 老师持仓
POST   /api/holdings          # 添加持仓
PUT    /api/holdings/:id      # 更新持仓
DELETE /api/holdings/:id      # 删除持仓
POST   /api/tips              # 发起打赏
GET    /api/tips/:teacher_id  # 打赏记录
POST   /api/follow/:teacher_id  # 关注老师
```

## 六、风险与注意事项

### 法律风险
1. **资金池问题** — 虚拟积分系统涉及资金池，需要支付牌照
2. **证券投资建议** — 不能有"跟单"、"代操盘"功能
3. **ICP备案** — 国内运营必须备案
4. **隐私保护** — 用户数据需要加密存储

### 技术风险
1. **数据安全** — 持仓数据敏感，需要加密
2. **高并发** — 热门老师页面可能被刷
3. **行情接口** — 免费接口可能被限流

### 运营风险
1. **内容审核** — 需要审核老师发布的内容
2. **纠纷处理** — 打赏纠纷、虚假宣传
3. **税务问题** — 打赏收入需要报税
