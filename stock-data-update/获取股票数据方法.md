# SouAGu 股票数据获取与更新方法

> 本文档记录如何获取最新 A 股 / ETF / LOF 的**股票代码、名称、拼音简称**，以及数据更新流程中的所有细节。
> 数据源仅使用**腾讯股票 API**（`qt.gtimg.cn` 等腾讯接口），不使用其他任何非腾讯股票接口。
> 本次更新日期：2026-08-14。

---

## 一、数据来源与格式

### 1.1 主接口

```
http://qt.gtimg.cn/q=sh600000,sz000001,bj920038,...
```

- 以逗号分隔批量查询股票代码，**每个代码必须带市场前缀**（`sh` / `sz` / `bj`）。
- 一次请求建议不超过 **100 个**代码，避免超时。
- 响应编码为 **GBK**，需用 `decode('gbk')` 解析。
- 无效 / 退市 / 未收录的代码**会被直接忽略，不返回任何内容**（因此可以全量扫描）。

### 1.2 返回格式

每行形如：

```
v_sh600000="1~浦发银行~600000~10.12~...";
```

按 `~` 分割字段，取值方式：

| 字段索引 | 含义 |
|---|---|
| `[0]` | 市场状态标识（1） |
| `[1]` | **股票简称**（即我们要的名称） |
| `[2]` | 6 位数字代码 |
| `[3]` | 最新价 |
| `[30]` | 时间戳（`YYYYMMDDHHMMSS`），用于判断活股/退市股 |

### 1.3 市场前缀与代码段

| 市场 | 前缀 | 代码段 |
|---|---|---|
| 深圳 A 股主板 | `sz` | `000`-`003` |
| 创业板 | `sz` | `300`-`303` |
| 上海主板 | `sh` | `600`-`605`（601/603/605 实际在用） |
| 科创板 | `sh` | `688` |
| 北交所 | `bj` | `920` |
| 上海 ETF/基金 | `sh` | `510`-`518`、`560`-`563`、`588`-`589` |
| 深圳 ETF/LOF | `sz` | `159`、`160`-`169` |

### 1.4 全量扫描策略

由于腾讯会忽略无效代码，可以对**千位前缀 × 后三位 000-999** 做穷举，共扫描 **41 个千位区间、约 8000+ 个代码**。

```
PREFIX_RANGES = [
    (0,'sz'), (1,'sz'), (2,'sz'), (3,'sz'),
    (300,'sz'), (301,'sz'), (302,'sz'), (303,'sz'),
    (600,'sh'), (601,'sh'), (603,'sh'), (605,'sh'),
    (688,'sh'),
    (920,'bj'),
    (510,'sh'), (511,'sh'), (512,'sh'), (513,'sh'),
    (515,'sh'), (516,'sh'), (517,'sh'), (518,'sh'),
    (560,'sh'), (561,'sh'), (562,'sh'), (563,'sh'),
    (588,'sh'), (589,'sh'),
    (159,'sz'), (160,'sz'), (161,'sz'), (162,'sz'),
    (163,'sz'), (164,'sz'), (165,'sz'), (166,'sz'),
    (167,'sz'), (168,'sz'), (169,'sz'),
]
```

每次批量查询后 `time.sleep(0.05)` 限速，避免被限制。

### 1.5 活股 / 退市股判定

- **活股**：时间戳为当天实时交易时间（如 `20260814153548`，时间部分 `> 0930`）。
- **退市 / 历史股**：时间戳为固定值 `YYYYMMDD090000`（09:00）或 `YYYYMMDD091000`（09:10），不是实时行情。

```python
def is_live(ts):
    if not ts or len(ts) < 12:
        return False
    return ts.startswith('20260814') and ts[8:12] > '0930'
```

> 注意：这里的 `20260814` 是扫描当天日期，需按实际运行日期调整。

## 二、名称规范化处理规则

腾讯返回的名称需要经过规范化才能入库，规则如下（按顺序应用）：

### 2.1 压缩空格

腾讯返回的名称常带对齐空格，需合并连续空格：

```python
import re
def compress_spaces(name):
    return re.sub(r'\s+', ' ', name).strip()
```

### 2.2 去除 C/N 前缀（上市初期标记）

新股上市前 5 个交易日简称会带 `C`（主板/创业板）或 `N` 前缀，如 `C超纯应材`。需去掉：

```python
if len(name) > 1 and name[0] in ('C', 'N') and name[1] != ' ':
    name = name[1:]
```

### 2.3 去除 -U 后缀（未盈利标记）

科创板未盈利企业简称带 `-U` 后缀，如 `泰诺麦博-U`：

```python
if name.endswith('-U'):
    name = name[:-2]
```

### 2.4 去除 -W 后缀（同股不同权标记）

科创板同股不同权企业简称带 `-W` 后缀，如 `优刻得-W`：

```python
if name.endswith('-W'):
    name = name[:-2]
```

### 2.5 分红除息（XD/XR/DR）保护

当股票当日分红除息时，腾讯会返回 `XD/XR/DR + 截断名称`（如 `XD中铁工` 实为"中铁工业"），此时**必须保留旧数据中的原名称**，不能直接采用腾讯名称：

```python
def is_dividend_name(n):
    return n.startswith(('XD', 'XR', 'DR'))
```

## 三、腾讯名称截断问题（重要坑）

### 3.1 10 字节限制

腾讯 `qt.gtimg.cn` 对名称字段有 **10 字节（GBK 编码）** 限制。超过该长度的名称会被**从中间截断**。

示例（2026-08-14 实测）：

| 完整名称 | GBK 字节数 | 腾讯返回 |
|---|---|---|
| `C国仪公司-U` | 11 字节（超限） | `C国仪-U`（被截断） |
| `C超纯应材` | 9 字节 | `C超纯应材`（完整） |
| `泰诺麦博-U` | 10 字节 | `泰诺麦博-U`（完整） |
| `宇树科技-W` | 10 字节 | `宇树科技-W`（完整） |

字节计算：GBK 下汉字 2 字节、英文字母 1 字节。

### 3.2 影响范围

该问题**只影响同时带 C 前缀 + 4 字名称 + -U/-W 后缀**的极端情况（即名称超长）。2026-08-14 更新中**仅 688828 一只**受影响（真实简称"国仪公司"，被截断为"C国仪-U"）。

### 3.3 解决办法：人工修正表

腾讯所有接口（行情、K线、公司资料）均返回截断名，无法从腾讯获取完整名称。通过交易所/发行公告核实后，在脚本中维护**人工修正表**：

```python
MANUAL_FIX = {
    '688828': '国仪公司',
}

def apply_manual_fix(code, name):
    return MANUAL_FIX.get(code, name)
```

## 四、拼音首字母生成

使用 `pypinyin` 库：

```python
from pypinyin import lazy_pinyin, Style

def pinyin_initials(name):
    clean = name.replace('*', '')  # 处理 *ST 前缀
    initials = lazy_pinyin(clean, style=Style.FIRST_LETTER)
    return ''.join(i.upper() for i in initials if i and i != ' ')
```

**关键细节：**

- **`*ST` 前缀必须先去掉 `*` 再生成拼音**。否则 `pypinyin` 会把 `*ST` 当作整体处理，结果错误（如 `*ST国华` 应生成 `STGH` 而非 `XSTGH`）。
- 生成后统一转为**大写**、去掉空格。
- **名称未变的旧记录保留原拼音**，不做重新生成——因为 `pypinyin` 对多音字的处理可能与旧数据不一致（例如"中联重科"旧数据拼音为 `ZLCK`，而 `pypinyin` 会生成 `ZLZK`）。只有新增或名称变化的记录才重新生成拼音，确保多音字与历史数据一致。

### 4.2 多音字拼音修正表（POLYPHONIC_FIX）

`pypinyin` 对部分多音字的**默认读音**与公司名/行业名的实际读法不符。名称未变的旧记录虽保留原拼音，但旧数据本身存在一批多音字错误，需要人工确认后通过 `POLYPHONIC_FIX` 覆盖（key 为股票代码，value 为修正后的主拼音，ST 股的原名称拼音在覆盖后仍会追加）。

**常见规则（人工核实）：**

| 字 | 正确读音 | 例子 |
|---|---|---|
| 重 | 重工业/重型装备读 `zhòng(Z)` | 中联重科 `ZLZK`、三一重工 `SYZG`、中国重汽 `ZGZQ`、国机重装 `GJZZ` |
| 重 | 地名"重庆"读 `chóng(C)` | 重药控股 `CYKG`、重百集团 `CBJT`（保留，不修正） |
| 藏 | 西藏的"藏"读 `zàng(Z)` | 西藏矿业 `XZKY`、奇正藏药 `QZZY` |
| 行 | 动词/出行读 `xíng(X)` | 三人行 `SRX`、通行宝 `TXB`、并行科技 `BXKJ` |
| 行 | 机构/商行读 `háng(H)` | 张家港行 `ZJGH`、华致酒行 `HZJH`、世联行 `SLH`（保留） |
| 长 | 公司名"长"多读 `cháng(C)` | 长鑫科技 `CXKJ`、长信医疗LOF `CX...`、长盛LOF `CS...`、长三角 `CSJ` |
| 厦 | 除"大厦"外多读 `xià(X)` | 华厦眼科 `HXYK`、广厦环能 `GXHN`、亚厦 `YXGF`（保留） |
| 乐 | 公司名读 `lè(L)` | 飞乐音响 `FLYX`、乐歌股份 `LGGF`（保留） |
| 朝 | 公司名读 `cháo(C)` | 朝阳科技 `CYKJ`（保留） |
| 阿 | 东阿/阿胶读 `ē(E)` | 东阿阿胶 `DEEJ` |
| 调 | 空调的"调"读 `tiáo(T)` | 哈空调 `HKT` |

修正表当前覆盖 **53 只**股票，均为人工核实的确定错误。运行 `update_stocks.py` 时对 `i` 字段直接覆盖。

### 4.1 ST 股双拼音（单字段逗号分隔）

ST 股（`ST`/`*ST` 开头）支持**两个拼音**：当前 ST 名拼音 + 原名称（戴帽前简称）拼音。二者合并存放在**同一个 `i` 字段**中，逗号分隔：

```
i: "STHW,HWSW"   // ST海王 / 海王生物
i: "STML,MLST"   // *ST美丽 / 美丽生态
```

**顺序规则（重要）：**

- **逗号前 = 主拼音（ST 名）**，逗号后 = 原名称拼音。
- 原因：搜索组件对 `i` 做**前缀匹配**。未升级的旧版 JS 会把整个字符串当作一个 key 插入 Trie，此时**只有逗号前的主拼音能作为前缀被搜到**。把 ST 名放前面，可保证旧代码下 ST 名搜索依然可用；升级后的新代码按逗号拆分后，两个拼音都能搜到。
- 主拼音与原名拼音相同时（如 `ST喜临门` 原名即"喜临门"），不追加，`i` 保持单值。

**搜索组件匹配逻辑：**

```js
// 新版 SouAGu.js _buildIndex：按逗号拆分后逐个插入 Trie
if (s.i) {
  var keys = s.i.split(',');
  for (var k = 0; k < keys.length; k++) {
    if (keys[k]) this._insert(keys[k].toUpperCase(), s);
  }
}
```

- **升级后**：两个拼音都可作为前缀搜索（如输入 `HWSW` 或 `STHW` 都能搜到 000078）。
- **未升级**：只有主拼音（ST 名）可搜，原名称拼音搜不到——这是预期行为，不是退化。

**数据来源**：原名称（戴帽前简称）腾讯 API 不提供，通过 web 搜索核实的公司更名公告维护在 `st_orig_names.json`（207 只 ST 股全部覆盖）。

## 五、新旧数据合并逻辑

### 5.1 数据记录格式

```json
{ "c": "600036", "n": "招商银行", "i": "ZSYH" }
```

- `c` = 6 位代码
- `n` = 股票简称（规范化后）
- `i` = 拼音首字母（大写）

### 5.2 合并规则

| 场景 | 处理 |
|---|---|
| 旧数据有 + 腾讯有，且腾讯名为 XD/XR/DR | **保留旧名称**（分红保护） |
| 旧数据有 + 腾讯有，名称不同（非分红） | 用腾讯规范化后的名称更新；基金记为"换简称" |
| 旧数据有 + 腾讯有，名称相同 | 保留旧记录（含旧拼音） |
| 旧数据有 + 腾讯扫描不到 | 保留旧记录 |
| 腾讯新增 + 时间戳为实时 | 加入，名称规范化，重新生成拼音 |
| 腾讯新增 + 时间戳为固定值 | **跳过**（退市/历史代码不加入） |

### 5.3 基金（ETF/LOF）名称处理

旧数据中基金名称来自东方财富（完整长名），本次更新统一**改为腾讯场内简称**（如 `养殖ETF华安`）。统计为 `fund_renamed`。

### 5.4 已退市股票

腾讯对已退市股票返回退市名（如 `*ST国华` -> `国华退`）。旧数据中已存在的退市股保留代码，名称更新为退市名。

### 5.5 ST 股原名称拼音

- 读入 `st_orig_names.json`（`{代码: 原名称}`），对每个 ST 股在其 `i` 字段追加 `,原名称拼音`（详见 4.1）。
- 该映射表由 web 搜索核实的公司更名公告维护，腾讯 API 无法提供此类历史简称。

## 七、更新流程（步骤总结）

1. **全量扫描**：运行 `fetch_tencent.py`，通过腾讯 API 穷举 41 个千位区间，得到 `{code: {n: 名称, p: 价格, t: 时间戳}}`，保存到 `tmp/tencent_raw.json`。
2. **合并与规范化**：运行 `update_stocks.py`，读取旧数据 + 扫描结果，按第五章规则合并，应用第二、三章的规范化与人工修正，生成拼音。
3. **人工核对新增股名称**：检查新增股票名称是否被腾讯截断（重点是带 C/N 前缀 + -U/-W 后缀的新股），截断的用发行公告核实后加入 `MANUAL_FIX`。
4. **验证**：
   - 无重复代码
   - 无空字段
   - 无残留 C/N 前缀、-U/-W 后缀
   - 名称未变记录的拼音 0 差异
   - `*ST` 前缀股票拼音正确
5. **输出并人工确认**：检查 `UPDATE_REPORT.txt` 与 `stocks-data.js` 无误后，再替换根目录数据文件。

## 八、常见问题（FAQ）

**Q1：为什么有的股票搜不到？**
扫描基于千位前缀穷举，若代码不在已列出的 41 个区间内（例如某些历史代码段），不会收录。可补充对应前缀后重新扫描。

**Q2：为什么新增股名称是 2 个字？**
可能是腾讯 10 字节限制导致的截断（见第三章）。需要人工核实真实简称并加入 `MANUAL_FIX`。

**Q3：为什么 `XD` 开头的名称没有更新？**
当日分红除息股票腾讯返回 `XD+截断名`，为避免错误，此类股票一律保留旧名称。

**Q4：为什么有的拼音和别处查的不一样？**
项目使用 `pypinyin` 的默认读音；为与历史数据保持一致，名称未变的旧记录不重新生成拼音（保留原值）。如需修正可人工覆盖 `i` 字段。

**Q5：运行报 `ModuleNotFoundError`？**
本仓库使用 `uv` 管理 Python 环境，所有命令需通过 `uv run python ...` 执行，不要直接使用 `python3`。
